# ADR-0001：先建立契约，再实现 Windows 控制平面

- 状态：Accepted
- 日期：2026-08-11

## 背景

现有多个独立项目运行在同一 Windows 主机，部分服务由共享 PM2 daemon 管理。项目数量和运行类型持续增长，单个项目运维 GUI 已经无法可靠解决进程归属、端口冲突、环境安装、更新回滚和统一审计。

## 决策

采用“一个统一 Console、每台主机一个 Agent、每个项目一套声明”的控制平面。先建立五类版本化契约和校验工具，再实现只读 Agent、安全控制、部署事务和 Console。

Windows SCM、IIS 和 Task Scheduler 是正式适配器；PM2 仅作为遗留适配器。业务进程不主动注册，部署者或 Console 将经过验证的发布交给 Agent。

## 结果

- 项目团队可以在 Agent 完成前开始补齐可审查的运维声明。
- Agent 不需要推断任意项目结构或执行项目提供的任意脚本。
- Windows 专属实现被限制在适配器层，契约和发布审计保持稳定。
- 初期需要同时维护契约、示例和适配器能力矩阵，不能用一个大而自由的配置文件快速绕过设计。
